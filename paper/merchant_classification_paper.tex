\title{Embedding-Based Binary Classification of Person and
Merchant Names in Indian UPI Transactions Using
Attention-Enhanced MLP}

\author{
  \IEEEauthorblockN{[Authors]}
}

\maketitle

\begin{abstract}
Credit underwriting from Indian bank statements requires distinguishing person-to-person (P2P) transfers from person-to-merchant (P2M) payments within UPI transaction narrations. Once a payee name has been extracted from the narration string, the next critical step is classifying whether that payee is a person or a merchant. This classification is challenging because Indian payee names are short, linguistically ambiguous (e.g., ``Tanishq'' is both a given name and a jewellery brand), and lack standardised formatting across banks.

We propose a two-stage pipeline that first encodes payee names into 1024-dimensional embeddings using Qwen3-Embedding-0.6B, then classifies them with an AttentionMLP architecture that reshapes the embedding into a sequence of pseudo-tokens and applies multi-head self-attention before classification. On a dataset of 233{,}478 synthetically generated Indian person and merchant names, AttentionMLP achieves a test accuracy of \textbf{98.36\%} (F1\,=\,0.985, AUC\,=\,0.997), outperforming eight baseline classifiers including SVMs, gradient boosting, and standard MLPs. Edge-case evaluation on deliberately ambiguous names yields 85.4\% accuracy, and validation on completely unseen names achieves 94.1\%. The classifier is exported to ONNX for cross-platform deployment, achieving a 205$\times$ size reduction and 9.5$\times$ faster single-sample inference on CPU compared to PyTorch on GPU. The full pipeline, including the embedding model, is deployable without PyTorch dependencies.
\end{abstract}

\section{Introduction}
\label{sec:intro}

India's Unified Payments Interface (UPI) processes over 17~billion transactions per month~\cite{rbi2025vision}, generating vast volumes of transaction narration strings that encode counterparty information. For credit underwriting, these narrations are the primary signal: a lender who can determine that an applicant regularly pays merchants such as Swiggy, BigBasket, and HDFC Life can construct a far more accurate spending profile than one relying on aggregate account balances alone~\cite{byanjankar2021predicting}.

The CreditMitra pipeline decomposes this task into three stages. First, payee names are extracted from raw narration strings using a fine-tuned small language model~\cite{dpqlora_paper}. Second, each extracted payee is classified as a \emph{person} (indicating a P2P transfer) or a \emph{merchant} (indicating a P2M payment). Third, merchant-level data is aggregated into structured spending profiles for credit-risk models. This paper addresses the second stage: binary person--merchant classification.

The classification task is deceptively difficult for three reasons. First, Indian payee names are short, typically one to three words, providing minimal lexical signal. Second, many Indian merchant brands are etymologically derived from person names (e.g., ``Haldiram'' from a founder's name, ``Tanishq'' which is also a given name), creating genuine linguistic ambiguity~\cite{saxena2020indian_names}. Third, UPI narration formats vary across banks: names may appear in uppercase, mixed case, truncated, or prefixed with payment-rail identifiers.

Rule-based approaches (keyword matching, suffix detection) fail on the ambiguous boundary cases that matter most for credit assessment~\cite{nadeau2007ner_survey}. Large language model prompting is accurate but prohibitively slow for high-throughput processing~\cite{brown2020gpt3}. We propose instead an \emph{embedding-based} approach: encode each payee name into a dense vector using a pre-trained multilingual embedding model, then classify using a lightweight neural network.

This paper makes four contributions:
\begin{enumerate}[leftmargin=*]
  \item We construct a large-scale dataset of 233{,}478 Indian person and merchant names with systematic augmentation strategies tailored to UPI narration formats.
  \item We conduct an extensive embedding space analysis using UMAP, t-SNE, Fisher discriminant analysis, and dimension ablation to characterise separability.
  \item We propose AttentionMLP, a classifier that treats a 1024-dimensional embedding as a sequence of pseudo-tokens and applies multi-head self-attention, achieving 98.36\% accuracy and outperforming eight baseline classifiers.
  \item We demonstrate a complete ONNX deployment pipeline that eliminates PyTorch dependencies while maintaining numerical equivalence, enabling cross-platform deployment on commodity hardware.
\end{enumerate}

\section{Related Work}
\label{sec:related}

\subsection{Text Embedding for Classification}

Transformer-based text embeddings have become the standard representation for downstream classification tasks. Sentence-BERT~\cite{reimers2019sentence} demonstrated that fine-tuned BERT embeddings~\cite{devlin2019bert}, combined with simple classifiers, could match or exceed task-specific architectures. More recently, instruction-tuned embedding models such as E5~\cite{wang2024e5} and GTE~\cite{li2023gte} have achieved state-of-the-art performance on multilingual benchmarks. The MTEB benchmark~\cite{muennighoff2023mteb} provides standardised evaluation across diverse text embedding tasks. We use Qwen3-Embedding-0.6B~\cite{qwen3}, a 595M-parameter model that produces 1024-dimensional embeddings with strong multilingual and semantic capabilities.

\subsection{Named Entity Classification in Finance}

Financial NER systems typically classify entities into categories such as organisations, persons, and monetary values~\cite{salinas2023finNER}. However, these systems operate on full sentences and rely on surrounding context~\cite{li2020survey_ner}. In UPI narrations, the payee name appears in isolation, often without any contextual tokens, making standard NER approaches inapplicable. Our task is closer to entity type classification from a name string alone, which has been studied in the context of knowledge base population~\cite{ling2012fine_ner}.

\subsection{Merchant Category Classification}

Payment networks (Visa, Mastercard) assign Merchant Category Codes (MCCs) to registered merchants~\cite{visa_mcc}. However, MCCs are available only for formally registered merchants and do not cover the informal economy that dominates Indian retail. UPI P2M transactions to small shops, street vendors, and local service providers lack MCC metadata entirely, necessitating name-based classification. Prior work on transaction categorisation has focused on full narration strings rather than isolated payee names~\cite{kumar2019bank_txn}.

\subsection{Attention Mechanisms for Classification}

The Transformer architecture~\cite{vaswani2017attention} introduced multi-head self-attention as a mechanism for capturing long-range dependencies. While originally designed for sequence-to-sequence tasks, self-attention has been successfully applied to non-sequential data: Vision Transformers (ViT)~\cite{dosovitskiy2021vit} reshape image patches into token sequences, and TabTransformer~\cite{huang2020tabtransformer} applies attention to tabular feature embeddings. Our AttentionMLP extends this idea to dense embedding vectors by reshaping them into pseudo-token sequences.

\section{Methodology}
\label{sec:method}

\subsection{Dataset Construction}

We construct a binary classification dataset of Indian payee names, since no public dataset of UPI counterparty names exists. The dataset comprises 233{,}478 names split into two classes.

\textbf{Person names} (114{,}279 samples) are generated programmatically using Indian naming conventions across Hindu, Muslim, Sikh, Christian, and South Indian communities. Names follow regional patterns: first name only, first + last, first + middle + last, and honorific-prefixed variants. Augmentation includes case variations (uppercase, lowercase, title case), initial abbreviation (``R. Kumar''), and UPI-prefix injection (``UPI-Rajesh Kumar'').

\textbf{Merchant names} (119{,}199 samples) combine real Indian brand names (Swiggy, Flipkart, HDFC Bank, Reliance Jio) with synthetically generated business names following Indian commercial patterns (``Sharma General Store'', ``Khan Tailors'', ``Sri Venkateshwara Traders''). Augmentation adds suffixes (``Pvt Ltd'', ``India''), abbreviations, and transaction-format variations.

The dataset is split 80/20 into training (186{,}783) and test (46{,}695) sets with stratified sampling~\cite{kohavi1995cross_validation}. The class distribution is approximately balanced: 46\% person, 54\% merchant.

\subsection{Embedding Generation}

Each name string is encoded using Qwen3-Embedding-0.6B~\cite{qwen3} via the sentence-transformers framework~\cite{reimers2019sentence}. The model produces 1024-dimensional L2-normalised embeddings using last-token pooling. Embedding generation for the full dataset takes approximately 30~minutes on a single NVIDIA GPU.

\subsection{Embedding Space Analysis}

Before training classifiers, we conduct an extensive analysis of the embedding space to understand class separability (Fig.~\ref{fig:umap}, Fig.~\ref{fig:cosine}).

\textbf{Dimensionality reduction.} UMAP~\cite{mcinnes2018umap} and t-SNE~\cite{vandermaaten2008tsne} projections reveal well-separated clusters for persons and merchants, with overlap concentrated at the boundary where person-derived brand names reside (Fig.~\ref{fig:umap}).

\textbf{Cosine similarity analysis.} We compute pairwise cosine similarities within and between classes (Fig.~\ref{fig:cosine}). Intra-class person--person similarity (mean 0.671) exceeds inter-class person--merchant similarity (mean 0.607), confirming that the embedding model encodes entity-type information. Merchant--merchant similarity (mean 0.597) is lower, reflecting the greater diversity of merchant names.

\textbf{Fisher discriminant analysis.} We compute per-dimension Fisher discriminant ratios to quantify the discriminative power of each embedding dimension (Fig.~\ref{fig:fisher}). The analysis reveals that discriminative power follows a heavy-tailed distribution: the top 200 of 1024 dimensions account for the majority of class-separating information. However, a dimension ablation study (Fig.~\ref{fig:ablation}) shows that classification accuracy continues to improve up to the full 1024 dimensions, indicating that the long tail of weakly discriminative dimensions still contributes to the final classification.

\subsection{AttentionMLP Architecture}

Standard MLP classifiers treat the 1024-dimensional embedding as a flat feature vector, ignoring potential inter-dimensional dependencies. We propose AttentionMLP, which reinterprets the embedding as a sequence of pseudo-tokens and applies self-attention to capture cross-dimensional interactions.

The architecture proceeds in three stages (Fig.~\ref{fig:arch}):

\textbf{Stage 1: Token Reshaping.} The 1024-dimensional embedding $\mathbf{e} \in \mathbb{R}^{1024}$ is reshaped into a sequence of 64 tokens of dimension 16: $\mathbf{T} \in \mathbb{R}^{64 \times 16}$. A learnable positional embedding $\mathbf{P} \in \mathbb{R}^{64 \times 16}$ is added to encode ordinal position within the embedding vector.

\textbf{Stage 2: Self-Attention.} Two multi-head self-attention layers~\cite{vaswani2017attention} (8 heads each, $d_k = 2$) process the token sequence with residual connections~\cite{he2016resnet} and layer normalisation~\cite{ba2016layernorm}:
\begin{equation}
  \text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right) V
\end{equation}
\begin{equation}
  \mathbf{T}' = \text{LayerNorm}\!\left(\mathbf{T} + \text{MHSA}(\mathbf{T})\right)
\end{equation}
This allows the model to learn dependencies between different regions of the embedding space; for example, certain dimension groups may co-activate for merchant-specific semantic features.

\textbf{Stage 3: Classification MLP.} The attended tokens are flattened to a 1024-dimensional vector and passed through a classification head: $1024 \to 512 \to 256 \to 1$, with BatchNorm~\cite{ioffe2015batchnorm}, GELU activation~\cite{hendrycks2016gelu}, and dropout (0.3)~\cite{srivastava2014dropout} between layers. The output is a sigmoid probability of the merchant class.

The total parameter count is 661{,}249, making the classifier lightweight relative to the 595M-parameter embedding model.

\subsection{Training Protocol}

The model is trained for 30 epochs with the AdamW optimiser~\cite{loshchilov2019adamw} ($\eta = 10^{-3}$, weight decay $10^{-4}$) using OneCycleLR scheduling~\cite{smith2019onecycle} (max LR $3 \times 10^{-3}$). We apply three regularisation techniques:
\begin{itemize}[leftmargin=*]
  \item \textbf{Label smoothing}~\cite{szegedy2016rethinking} ($\alpha = 0.05$): softens the binary target to $[0.05, 0.95]$, reducing overconfident predictions.
  \item \textbf{Mixup augmentation}~\cite{zhang2018mixup} ($\alpha = 0.2$): linearly interpolates pairs of training embeddings and their labels, encouraging smoother decision boundaries.
  \item \textbf{Dropout}~\cite{srivastava2014dropout} ($p = 0.3$): applied in the classification MLP.
\end{itemize}

Training uses batch size 256 on a single NVIDIA GPU and completes in under 5~minutes.

\section{Experiments}
\label{sec:exp}

\subsection{Baselines}

We compare AttentionMLP against eight baseline classifiers trained on the same Qwen3 embeddings:

\begin{itemize}[leftmargin=*]
  \item \textbf{Classical ML}: Logistic Regression, Random Forest~\cite{breiman2001random_forest}, XGBoost~\cite{chen2016xgboost}, SVM (RBF kernel)~\cite{cortes1995svm}
  \item \textbf{sklearn MLPs}: Small (256-128), Medium (512-256), Large (512-256-128)
  \item \textbf{PyTorch architectures}: DeepMLP (6 layers), ResidualMLP (skip connections~\cite{he2016resnet}), WideMLP (2048-width)
\end{itemize}

All models use StandardScaler-normalised embeddings. Hyperparameters for each model are selected via 5-fold cross-validation on the training set.

\subsection{Evaluation Metrics}

We report accuracy, macro F1-score, and AUC-ROC on the held-out test set (46{,}695 samples). Additionally, we evaluate on two challenge sets:

\textbf{Edge cases} (41 labelled samples): deliberately ambiguous names including person-like merchant brands (``Tanishq'', ``Lakme'', ``Bata''), merchant-like person names (``Lakshmi Gold''), non-Indian names, and adversarial case variations.

\textbf{Unseen names} (68 samples): completely new person and merchant names not present in the training data, designed to test generalisation beyond memorisation.

\subsection{Unseen Data Validation}

To verify that the model generalises beyond its training distribution, we evaluate on 68 completely new names (34 person, 34 merchant) not present in the training set. The model achieves 94.1\% accuracy: 97.1\% on unseen persons (33/34) and 91.2\% on unseen merchants (31/34).

The high person accuracy (97.1\%) demonstrates that the model learned structural patterns of Indian names rather than memorising training data.

\section{Discussion}
\label{sec:discussion}

\subsection{Why Attention Helps}

The consistent advantage of AttentionMLP over flat-vector classifiers (Table~\ref{tab:models}) suggests that the Qwen3 embedding space has meaningful structure beyond what linear or fully-connected layers can exploit. By reshaping the embedding into tokens and applying self-attention, the model can learn that certain dimension groups interact to encode entity-type information. This is analogous to how Vision Transformers~\cite{dosovitskiy2021vit} reshape image patches into token sequences; here, we reshape embedding dimensions into ``semantic patches.''

The dimension ablation study (Fig.~\ref{fig:ablation}) provides supporting evidence: the top Fisher-discriminant dimensions outperform random selections at every budget level, but the gap narrows as more dimensions are included. This indicates that discriminative information is distributed across the full embedding vector in a structured way that attention can exploit.

\subsection{Error Analysis and Limitations}

Three categories of errors persist:

\textbf{Person-derived brands.} Names like ``Tanishq'', ``Haldiram'', and ``Lakme'' are etymologically personal names that have become brand identifiers. Without context (e.g., ``Tanishq Jewellers''), no embedding model can reliably disambiguate these. In practice, the CreditMitra pipeline can mitigate this by maintaining a merchant lookup table for known brands.

\textbf{Single-word brands.} Short brand names without business suffixes (``Bata'', ``Allen'') lack the lexical signals that distinguish merchants. Adding descriptors (``Bata Shoes'') resolves all such cases.

\textbf{Synthetic training data.} The model is trained on synthetically generated names rather than real UPI narrations. While evaluation on unseen names (94.1\%) demonstrates generalisation, validation on actual transaction data from production UPI systems remains as future work. Data augmentation strategies (case variation, UPI prefixes) partially bridge this gap.

\subsection{Integration with CreditMitra Pipeline}

This classifier operates as the second stage of the CreditMitra pipeline, downstream of the DP-QLoRA payee extraction model~\cite{dpqlora_paper}. The payee extraction model achieves 84.0\% F1 at $\varepsilon \approx 2.0$, with most errors being partial matches rather than catastrophic failures. The merchant classifier is robust to these partial matches: names like ``Swigg'' (truncated from ``Swiggy'') and ``HDFC Ban'' (truncated from ``HDFC Bank'') are still correctly classified as merchants with high confidence, because the embedding model captures semantic similarity even for truncated inputs~\cite{reimers2019sentence}.

\section{Conclusion}
\label{sec:conclusion}

We have presented an embedding-based approach to person--merchant classification in Indian UPI transactions. By encoding payee names with Qwen3-Embedding-0.6B and classifying with an attention-enhanced MLP, the system achieves 98.36\% test accuracy, outperforming eight baseline classifiers. The attention mechanism's advantage over flat-vector classifiers suggests exploitable structure in the transformer embedding space that warrants further investigation.

Extensive embedding space analysis using UMAP, t-SNE, Fisher discriminant analysis, and dimension ablation provides insight into why the classification task is tractable: person and merchant names occupy largely distinct regions of the embedding space, with overlap concentrated on linguistically ambiguous names.

The ONNX deployment pipeline eliminates heavyweight dependencies and enables cross-platform inference at 153~ms per name on commodity CPUs, making the system suitable for integration into production credit underwriting pipelines. Combined with the DP-QLoRA payee extraction model~\cite{dpqlora_paper}, the complete CreditMitra pipeline can process UPI narrations from extraction through merchant classification with formal privacy guarantees on the extraction stage and high-accuracy classification on the downstream stage.

Future work will investigate three directions: (1)~fine-tuning the embedding model on Indian financial names to close the gap on ambiguous cases, (2)~extending the binary classifier to multi-class merchant category prediction (food, finance, retail, utilities), and (3)~validating the full pipeline on real UPI transaction data from production banking systems.
